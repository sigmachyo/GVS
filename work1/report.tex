\section*{ВВЕДЕНИЕ}
Цель работы -- освоить базовые навыки программирования CUDA, включая работу с одномерными сетками нитей и динамической памятью устройства, а также изучить паттерн проектирования Data + View.

Для достижения цели необходимо разработать шаблонные классы \texttt{Data}, \texttt{VectorView} и \texttt{Vector}, реализовать CUDA-кернел сложения векторов, перегрузить оператор \texttt{operator+}, проверить результаты с помощью Google Test и Eigen, а также исследовать производительность с помощью Google Benchmark.

\section{Разработка программного решения}
\subsection{Класс Data}
Класс \texttt{Data} владеет массивом в глобальной памяти устройства. Выделение памяти выполняется в конструкторе, освобождение -- в деструкторе, что соответствует идиоме RAII. Класс поддерживает копирование, перемещение и обмен данными с хостом.
\codefile{Data}{core/include/Data.cuh}

\subsection{Класс VectorView}
Класс \texttt{VectorView} хранит указатель на данные и их размер, не владея памятью. Объекты передаются в CUDA-кернел по значению. В тестах дополнительно проверяется свойство тривиальной копируемости.
\codefile{VectorView}{core/include/VectorView.cuh}

\subsection{Класс Vector}
Класс \texttt{Vector} является фасадом: агрегирует \texttt{Data} через \texttt{std::shared\_ptr} и содержит собственное представление \texttt{VectorView}. Для исключения выделения памяти из измеряемой части бенчмарка предусмотрен метод заполнения заранее созданного результата.
\codefile{Vector}{core/include/Vector.cuh}

\subsection{CUDA-кернел сложения}
Кернел принимает три объекта \texttt{VectorView} по значению. Каждый поток вычисляет индекс элемента и записывает сумму в выходной вектор.
\codefile{kernel\_vecadd}{core/include/kernel_vecadd.cuh}

\section{Тестирование корректности}
Для проверки \texttt{operator+} используются размеры
\[
 n \in \{1,2,3,127,128,129,512,1024,1029\}.
\]
Эталонный результат вычисляется с помощью \texttt{Eigen::VectorXf}. Проверка включает обязательный вызов \texttt{isApprox} с точностью $10^{-6}$ и отдельную проверку максимальной абсолютной погрешности, не превышающей $10^{-6}$.

\section{Экспериментальное исследование производительности}
Бенчмарки выполняются для размеров
\[
 n \in \{8,8^2,8^3,8^4,8^5,8^6,8^7,8^8\}.
\]
Для CUDA используются события CUDA Events API. Память входных и выходного векторов выделяется и заполняется до начала измеряемого цикла, поэтому в результат попадает время вычисления сложения, а не время управления памятью.

\section{Интерпретация результатов}
Теоретическая сложность по количеству элементов для сложения двух векторов равна $O(n)$, поскольку для каждого элемента выполняется одна операция сложения. Поэтому с увеличением $n$ время вычисления должно расти линейно.

На малых размерах CUDA может уступать Eigen из-за постоянных накладных расходов запуска кернела и синхронизации. При увеличении размера вектора параллельная обработка GPU должна уменьшать время вычисления относительно реализации на CPU. Фактические значения ускорения зависят от модели GPU, версии CUDA, настроек компилятора и параметров системы, поэтому в отчёт должны включаться только результаты, полученные на конкретной CUDA-машине.

\section*{ЗАКЛЮЧЕНИЕ}
В работе разработана шаблонная реализация сложения векторов на CUDA с использованием паттерна Data + View. Класс \texttt{Data} управляет памятью устройства по RAII, \texttt{VectorView} предоставляет тривиально копируемое представление данных, а \texttt{Vector} объединяет эти компоненты и предоставляет перегруженный оператор сложения.

Корректность решения проверяется сравнением с Eigen на заданных граничных размерах. Методика бенчмаркинга использует CUDA Events API и исключает выделение и освобождение памяти из измеряемого участка. Графики и окончательные численные выводы должны быть сформированы по фактическому файлу \texttt{benchmark\_results.json}.
